# Agent controls and boundaries

The workspace supports explicit agent choices, reusable profiles, custom teams and task templates. Role-specific configuration can include instructions, a model assignment, answer budget, sampling preference and automatic selection preference. These are product capabilities, not publication of internal prompts or implementation.

A role uses task-relevant context and the selected memory/knowledge settings. Configured choices are snapshotted for a run. Dependencies determine handoff order; a review pass checks the request and supplied evidence before final assembly where the workflow includes those stages. Users can cancel running work through the available controls.

A local model must be qualified and accepted before local inference. A connected model is a distinct account-backed route. Neither role names nor catalog size prove independent execution, universal accuracy or unrestricted parallelism. Custom teams have bounded specialist counts and resource-limited concurrency.

Meeting/note content uses the local-only policy in the current documented Windows baseline. Review relevant execution mode and context boundaries before other connected work.

The 536-role catalog contains coordination, review and specialist definitions. It is not a statement that all roles execute per request or that a review substitutes for tool evidence or qualified professional judgement.
