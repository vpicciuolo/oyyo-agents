## What an agent entry tells you

Each role card describes the workspace name, specialty, department, expected contribution, related coordination role and practical boundaries. This is a catalog of available roles, not 536 permanently running workers or a promise of universal professional expertise.

## Nested specialist structure

The catalog adds 336 delivery/validation roles beneath the 168 existing department specialists. Paths can run from a domain lead through a specialist and delivery specialist to a validation subagent. Parentage describes role specialization; the run plan determines which agents actually execute. Compatible builds can refresh role definitions through **Sync catalog**.

## From a request to a usable answer

A simple request can use one assistant pass. A complex task can use planning, bounded specialist assignments, review and final assembly. The user can inspect the real participating roles and status, provide follow-up instructions and request usable drafts or available exports.

Agents do not gain new account access, file permissions or tool capabilities merely by being selected. Posting, browsing, code execution, media generation and document export require the corresponding available tool. A drafted plan is not evidence of a completed external action.
